Preprint
Author: Richard Stein
Date: 24 September 2026

Abstract. This preprint describes a candidate engineering and evidence-governance framework for a three-bit fluid-junction machine. A binary state (b2,b1,b0) maps to an integer N and candidate connected-path count P=N+1. The work separates commanded state, connectivity, physical geometry, measured flow response, validation, and committed state. It correlates that separation with residential water-distribution topology, California Title 24 code-family structure, and Bitcoin Core's separation of block receipt from validation and accepted state processing. These correlations are architectural. They do not establish that the proposed mapping is a universal physical law, that a depicted machine has been physically validated, or that any design complies with California building codes. The paper formalizes the evidence boundary using the TCGE relation K=R∧I∧E and the invariant THROUGH(HOLD)≠PASS.

1. Research question

Can a fixed three-bit control representation be used as a disciplined indexing layer for candidate fluid-junction connectivity while preserving a strict boundary between command, physical implementation, measurement, validation, and state commitment?

The scoped claim investigated here is narrower than a universal-law claim. The present paper asks whether the representation is internally coherent and whether its governance structure has meaningful analogues in independently developed systems.

Boundary: P=N+1 is a candidate machine encoding. It is not asserted as a general law of plumbing or fluid networks. A tee and a wye can have the same port count while differing in geometry and hydraulic response.

3. Geometry and fluid response

Let Γ denote the physical geometry and U the fluid state. A candidate state-transition representation is:

U = (ρ, v, p, ...)
U(t+Δt) = F(U(t), u(t), Γ, N)

For a bounded junction control volume, familiar conservation relations provide testable observables:

Q = A v
Σ Q_in = Σ Q_out   [incompressible bounded case]
Σ ρ_i A_i v_i = 0   [mass balance with signed convention]

The binary command therefore cannot substitute for measurement. A requested 111 configuration defines a candidate eight-path configuration under this encoding; it does not prove that eight paths are physically open, hydraulically functional, or compliant with any performance criterion.

The GETHUB artifact in the project repository defines a Governed Evidence Transfer Hub that preserves source/object identity and separates transfer from admission. TCGE classifies material claims using:

R = sufficient direct evidence
I = interpretation or inference
E = sufficiently independent validation
K = R ∧ I ∧ E
H = I ∧ ¬K

These definitions make validation claim-specific. A byte-identical artifact can be known as byte-identical without thereby establishing semantic correctness, physical validity, or code compliance.

5. Residential water-distribution correlation

A residential potable-water network provides a useful topology comparison: source/service → main → junctions → branches → fixtures. Fixture demand, pipe diameter, pressure loss, material, length, elevation, backflow protection, and local requirements are separate engineering variables. The comparison supports the distinction between connectivity and physical performance, but does not imply that a household piping network follows the proposed three-bit encoding.

6. California Title 24 correlation and correction

The 2025 California Building Standards Code, California Code of Regulations Title 24, became generally effective on 1 January 2026. The California Building Standards Commission identifies Part 4 as the California Mechanical Code, Part 5 as the California Plumbing Code, Part 6 as the California Energy Code, Part 11 as CALGreen, and Part 12 as the California Referenced Standards Code.

For the residential potable-water diagram used in this research, Part 5, California Plumbing Code, is the primary candidate Title 24 branch, subject to project scope, jurisdiction, California amendments, errata, and local amendments. Refrigeration/mechanical components of a separate fluid-junction implementation may instead implicate Part 4, while controls and energy performance may implicate Parts 3 and 6 as applicable. This corrects any over-broad treatment of all fluid piping as a single Title 24 branch.

Compliance boundary. Correlation is not compliance. A repository record, hash, diagram, simulation, or architectural analogy does not establish code applicability, listing, approval, inspection acceptance, or compliance. Section-level authoritative source text and project-specific applicability remain required.

7. Bitcoin Core architectural correlation

Bitcoin Core independently separates receipt or submission of a candidate block from validation and accepted chain-state processing. Current Bitcoin Core source calls ProcessNewBlock, captures validation state, and distinguishes accepted, invalid, duplicate, and inconclusive outcomes. The bounded architectural correlation is therefore:

candidate object → receipt → validation → accepted/rejected state processing

correlated with

candidate state → THROUGH → GATE → LATCH/HOLD

This is a conceptual/architectural Echo for the separation principle only. Bitcoin Core does not implement, endorse, or validate GETHUB, TCGE, the three-bit fluid-junction mapping, or a universal physical formula.

8. Physical validation protocol

A prospective physical test of state 111 should preserve the following order:

COMMAND 111
→ record actuator positions
→ observe candidate configuration
→ measure all relevant paths
→ preserve untouched raw measurements and provenance
→ apply frozen pass/fail criteria
→ independent validation
→ GATE
→ PASS only if criteria are satisfied
→ LATCH physical-111

Useful observables may include path-open status, flow, differential pressure, leakage, repeatability, actuator position, temperature, and boundary conditions. The exact criteria must be frozen before execution if the result is intended to discriminate a hypothesis.

10. Falsifiers and next experiment

The physical implementation would fail a frozen state-specific claim if commanded connectivity does not match measured connectivity, if conservation residuals exceed predeclared tolerances after accounting for measurement uncertainty, if actuator state is ambiguous, if provenance is broken, or if an independent validation path contradicts the primary measurement. A future revision should define instrument accuracy, sampling rate, calibration, geometry, fluid, temperature, pressure range, exact acceptance tolerances, and an independent replication path before execution.

11. Conclusion

The current work supports a disciplined separation between symbolic state, physical connectivity, geometry, measured fluid response, validation, and committed state. Residential plumbing and Bitcoin Core provide independently developed architectural analogues for portions of that separation. California Title 24 provides a regulatory framework against which project-specific implementations can be mapped, with Part 5 being the primary candidate branch for residential potable-water systems. None of these correlations, alone or together, establish universal physical validity or code compliance. The next scientifically material step is a frozen, instrumented physical test with preserved raw evidence and a meaningfully independent validation path.
